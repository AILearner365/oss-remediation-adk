## Cause classification and production inspection

**Demonstrated:** applicable finding evidence was supplied but not fully used in the first accepted decision. The model substituted unsupported release expectations for observed project facts; one run explicitly converted blocked research into suggestive absence evidence, the other made the claim without research. Both carried unsupported premises into solution rationale. The error is in evidence reconciliation and completeness claims at decision time.

**Not demonstrated:** missing/truncated initial finding evidence, a harness selecting an insufficient version, lost official release evidence in these two runs, or an ambiguous instruction that uniquely explains the decisions. Root POM reads and command outputs can be partial, but the relevant parent and complete initial finding set were visible. Research feedback distinguishes transport acquisition from blocked extraction; treating that pair as contradictory technical evidence is unwarranted. No current external lookup can retroactively become evidence available to these models. This investigation makes no fresh assertion about the real availability or compatibility of any particular Spring release.

**Hypotheses only:** first/minimum-fix anchoring across repeated coordinates, stale model priors, long-context salience, and failed-search anchoring. The traces do not distinguish these internal causes or establish that more instructions, different ordering, or a different model would solve them.

Inspected `prompt.py` (`AGENT_INSTRUCTION`, `canonical_task_to_solve`, `initial_message`), `journal.py` (Q1–Q5, COMPLETE/PARTIAL rules and submission validation), research provider and toolset response construction, and prior changes. The canonical task serializes each target finding without collapsing by coordinate. Existing Q1/Q4/Q5 require complete-problem coverage and hard-constraint reconciliation; Q2/Q3 and the agent instruction explicitly reject absence inference from failed retrieval and give task/repository/current authoritative evidence precedence over unsupported expectations. `research_search` already says failure is not evidence of absence and exposes blocked/extraction/recovery fields. These policies predate `6b437a12`; `bd1d87b0` and `b84863f7` already addressed acquisition guidance and evidence chronology, with D34 separately identifying stale-version reasoning. From `6b437a12` to reviewed HEAD the relevant journal changes address incoming shape/repair and shared replay duplicate handling (`c0a4865a`, `93c30480`), not substantive reasoning. The source prompt and research provider did not change over that interval.

**Correction justified here:** close the development scenario/accepted-decision review gap. No demonstrated production defect warrants a runtime patch.
