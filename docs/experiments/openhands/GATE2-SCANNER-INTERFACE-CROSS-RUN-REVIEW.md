# Gate 2 — scanner interface correction and cross-run evidence

Date: 2026-10-11. **Correction to tool interface, not to remediation reasoning strategy.** No model, task contract, guidance, Maven Skill, independent scanner, validator, Stop Hook acceptance, denial budget or dependency version was changed.

## Reproduced mechanism in source

- `scripts/openhands/openhands-gate2-stop-hook-run.py::configure_scanner_terminal` prepends a session-scoped `scanner-bin` launcher to OpenHands terminal `PATH`, and provides `OPENHANDS_OSV_MAVEN_REGISTRY` pointing at a served local Maven repository along with `OPENHANDS_OSV_EXECUTABLE` pointing to the installed binary. The task adds instructions to use `osv-scanner` from PATH.
- Prior `scripts/openhands/openhands-osv-scanner.sh` applied `--data-source=native --maven-registry=...` **only** when arguments began `scan source`. The older `osv-scanner --format json -r .` invocation silently passed straight through to the executable without the Maven registry.
- Independent validation `scripts/openhands/openhands-gate2-validate.py` creates the same deterministic `OsvScanner` as baseline and uses `autonomous_oss_remediation_agent/deterministic/osv.py` to run `scan source` against a staged checkout with a served Maven local-repository registry. It consistently reported 10 scannable packages for Tasks 15 and 17. It is not a distinct vulnerability-scanner product.
- The new launcher **normalizes the confirmed legacy recursive source scan** (e.g. `osv-scanner --format json -r .`) into `osv-scanner scan source --format json -r . --data-source=native --maven-registry=<session URL>`. It also overrides agent-provided data-source/registry flags in canonical source commands to maintain the intended session registry. `--help`, `--version`, and SBOM subcommands pass through unchanged. Absent required registry, supported source scans fail with `INCOMPLETE_SCAN` instead of silently generating incomparable evidence. This fixes known invocation ambiguity; it does not guarantee success for every Maven project or scanner error.
- Regression fixture `scripts/openhands/osv-launcher-preflight.py` uses a fake scanner and no network, model or Maven calls to assert argument forwarding, normalization, overrides, unrelated-command pass-through, and fail-closed missing-registry behavior. **Offline test committed, execution in Cloud Shell not yet verified.**

## Attribution, limits and controlled follow-up

**Harness interface failure (confirmed):** a reasonable known legacy source invocation previously bypassed essential Maven registry configuration. This confounds agent assessment when the scanner provides incomplete evidence. The correction makes both known agent invocation shapes use the same native-registry configuration. It does not alter independent validation and does not justify ignoring scanner exit code/extraction errors.

**Agent variability (also confirmed):** Task-15 switched to a working scanner call quickly after inspecting help; Task-06 eventually used a valid SBOM fallback; Tasks 16/17 repeatedly treated incomplete source evidence as success. Version-verification mistakes, exclusion/compatibility analysis, unnecessary repeated builds and destructive cache operations remain distinct agent or isolation concerns.

**No claim of reasoning improvement:** changing the launcher changes a tool available to the model and is a deliberate experimental variable. Before any future live comparison, run the offline test, record control SHA and launcher file hash, confirm canonical and legacy commands hit the registry and scanner output/coverage, and compare the original 26-finding baseline and model parameters. Evaluate agent decision-making with the existing nine-dimension scorecard, per-attempt results and decision-level evidence. A subsequent live run tests scanner usability and the agent's response to valid findings, **not** solely an isolated reasoning-guidance effect. Do not run Task-18 as part of this interface correction.

**Independent safety follow-up:** per-run Maven local-repository isolation remains outstanding; normalizing scanner calls does not restrict the agent's shared cache deletion permissions. Existing conservative Maven-exclusion suppression-policy semantics remain unchanged and should be assessed separately.
