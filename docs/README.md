# Documentation

This directory contains the authoritative product and engineering documentation for the Enterprise OSS Remediation Platform.

## Document hierarchy

1. [Software Requirements Specification](./software-requirements-specification.md)
2. Architecture Document — to be created after the SRS is reviewed and baselined
3. Detailed Design Document — to be created after architecture approval
4. Requirements Traceability Matrix — maintained as requirements are mapped to architecture, design, implementation, and verification

## Governance

The Software Requirements Specification is the primary reference for:

- architecture validation
- design validation
- implementation scope
- test planning and verification
- release acceptance
- deferred requirement tracking

Architecture and design decisions must trace back to one or more approved requirements. Product verification must confirm that delivered behavior satisfies the applicable requirements and release scope.
