# Architecture Decision Records

This directory stores significant architecture decisions for the Enterprise OSS Remediation Platform.

Use one file per decision with the naming pattern:

`ADR-###-short-title.md`

Each ADR should include:

- status
- context
- decision
- alternatives considered
- consequences
- related business requirements
- related capabilities

Do not use ADRs for routine implementation details. ADRs are reserved for decisions that materially affect architecture, platform boundaries, integration strategy, data ownership, security, extensibility, or major tradeoffs.
